## 결론

현재 화면은 홈과 뉴스 목록 등 핵심 정적 레이아웃은 최신 Figma와 대체로 일치한다. 그러나 실제 사용 흐름을 막거나 신뢰를 훼손하는 기능 결함이 남아 있다. 가장 먼저 고쳐야 할 항목은 로컬 백엔드 미구현, 클래스 상세의 `0단계`, 분석 결과 이어보기 정지, 약관·비밀번호 재설정의 죽은 동작, 작은 화면에서 로그인 수단이 잘리는 문제다.

특히 “화면이 보인다”와 “기능이 완성됐다”를 구분해야 한다. 내 문장 분석, 억양 곡선, 마이 억양 특성, 알림, 구독, 공지, 문의는 현재 예시 또는 안내 UI이며 실데이터 기능이 아니다.

## 범위와 방법

- Figma 최신 기준 화면에서 홈, 뉴스 목록, 분석 결과 프레임을 직접 열어 렌더링 결과와 비교했다.
- 공개 라우트 6개와 인증 필요 라우트 15개를 Playwright로 순회했다.
- 뷰포트는 `390×844`, `1440×900`, 작은 화면 `375×667`을 사용했다.
- 정상 API 응답, 503 오류, 빈 상태, 상세 진입, 필터, 알림, 클래스 시작, 내 문장 입력, 연습 시작 상태를 확인했다.
- 브라우저 콘솔, 4xx/5xx 응답, 가로 오버플로, 상호작용 이름, 터치 타깃 크기를 수집했다.
- 소스의 실제 라우트 연결, API 어댑터 53개, 인접 `VC-BE` 컨트롤러를 교차 점검했다.

심각도는 다음 기준을 사용한다.

- `P0`: 릴리스 또는 핵심 종단 흐름을 막는 차단 결함
- `P1`: 주요 기능 실패, 데이터 오표시, 법적·계정 흐름 결함
- `P2`: 우회는 가능하지만 사용성·접근성·일관성을 크게 해치는 결함
- `P3`: 품질, 성능, 유지보수 또는 문구 수준 결함

## 디자인 비교에서 확인된 주요 차이

### 홈

Figma `11 Home · 시안 F 첫 방문`의 402px 카드 구조, 네 가지 진입 카드, 하단 내비게이션은 현재 구현과 거의 일치한다. 다만 Figma 첫 방문 문구는 “3문장이면 끝나요”이고 구현은 API 목표와 추천 상태를 사용한다. 이는 의도된 동적 치환인지 제품 확인이 필요하다.

### 뉴스 목록

카드, 색상, 카테고리 칩, 402px 폭은 대체로 일치한다. 구현에는 Figma에서 보이지 않는 난이도 필터 한 줄이 추가됐고, 카드 보조 메타데이터는 Figma보다 부족하다. 기능 결함 `UI-15`, `UI-17`, `UI-20`과 함께 정리해야 한다.

### 분석 결과

Figma `21 Result · 종합/발음 상세/속도와 억양`은 실제 문장별 점수, 플레이어, 발음 상세, 억양 비교를 전제로 한다. 현재 점수·세그먼트 API는 있으나 억양 곡선은 고정 예시다. 결과 이어보기는 개발 Strict Mode에서 완료 응답 후에도 `0%`에 고정돼 시각 비교 단계에 진입하지 못했다.

## 권장 처리 순서

1. `BE-01`, `UI-01`, `UI-02`, `UI-03`으로 종단 테스트 가능성과 데이터 무결성을 먼저 확보한다.
2. `UI-07`~`UI-10`의 약관·계정 복구·작은 화면 차단을 해결한다.
3. 신규 API 중 내 문장, prosody, 클래스 단계, 콘텐츠 taxonomy를 연결해 예시 데이터를 제거한다.
4. 마이 오류 격리와 목록 재시도를 공통 비동기 상태 패턴으로 정리한다.
5. 44px 터치 타깃, 색 대비, 이미지 경고, 포맷 591건을 품질 게이트로 자동화한다.

## 남은 위험

- Figma 파일에는 많은 변형 상태가 한 거대 프레임에 배치돼 있다. 이번 점검은 최신 기준으로 명시된 프레임과 대표 홈·뉴스·결과 화면을 확인했으며, 모든 숨김 레이어의 픽셀 단위 차이를 자동 추출한 것은 아니다.
- 실제 API 서버가 없어 음원 업로드, presigned URL, 폴링, 재생 URL 만료, 분석 실패 재시도는 계약 목으로만 확인했다.
- iOS Safari, Android WebView, 실제 safe-area, 소프트 키보드, 마이크 권한 거부/복구는 실기기 검증이 남아 있다.
- 색 대비 수치는 소스의 대표 조합 계산값이며 전체 화면 자동 접근성 감사 결과가 아니다.
