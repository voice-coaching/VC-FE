# 기준 발음 재생 경합 수정

기준: origin/dev `67f1121`, 브랜치 `fix/reference-audio-playback`.

`ReferencePlayer`는 API 응답 후 `setUrl()`과 DOM `src` 대입을 함께 수행하고 즉시 `play()`를 호출했다. React의 후속 src 갱신이 진행 중 재생을 중단할 수 있는 구조였다. 사용자 보고 오류와 일치하는 원인 후보이며 실제 운영 브라우저에서 재현한 결과는 아니다.

- React audio src prop을 제거하고 DOM 대입으로 관리 방식을 통일했다.
- contentId/source 변경 시 별도 플레이어 세션으로 교체한다. 이전 세션 정리 시 요청 순번을 무효화하고 재생을 중지한다. 늦은 API 응답은 이전/새 문장을 재생하지 않는다.
- 동기 ref로 요청 중 중복 클릭을 막는다. 일시 정지 후에는 현재 재생 위치를 이어가고, 종료 후 재생과 오류 후 재시도는 API에서 URL을 다시 받는다.
- 의도된 세션 정리로 발생하는 비동기 오류는 화면에 반영하지 않는다. 현재 요청의 AbortError에는 한국어 재시도 안내를 표시한다.

최신 dev의 예문·연습 데이터는 remote API를 사용한다. `src/lib/api/dev.ts`의 가상 데이터 정의는 남아 있지만 API 진입점에서 호출하지 않는다. 이 수정은 해당 미사용 파일 삭제나 DB/API 계약 변경을 포함하지 않는다.

검증: TypeScript `--noEmit --incremental false`, 변경 파일 ESLint, Prettier 검사, `git diff --check`. 운영 브라우저 재생, S3 권한 복구, TTS 실패 작업 재개는 이 프론트 수정의 검증에 포함하지 않았다.

배포 후 확인: 최초 기준 음성 재생, 일시 정지/이어 재생, 종료 후 재생, 요청 중 문장 전환, 음원 오류 후 재시도. 첫 재생 중 새 load로 중단되지 않고 이전 문장 응답이 새 문장에서 재생되지 않아야 한다.
