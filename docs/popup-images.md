# 팝업 이미지

관리자에서 기존 팝업을 먼저 저장한 뒤 같은 페이지의 ‘팝업 이미지’에서 PNG/JPEG(최대 3MiB)와 이미지 변경 사유를 입력해 첨부한다. 파일은 백엔드 경유로 검증·PNG 변환 후 S3 `popup-images/`에 저장된다. 클라이언트가 S3에 직접 PUT하지 않으므로 S3 업로드 CORS 변경은 필요하지 않다. 교체·해제도 지원하며 팝업 설정의 저장되지 않은 변경이 있으면 먼저 설정을 저장하도록 안내한다. 이미지 저장 중에는 설정 편집을 비활성화한다.

POST `/api/admin/popups/{popupId}/image`: multipart file/version/reason. DELETE 같은 경로: JSON version/reason. 활성 ADMIN·Bearer 필수, no-store. 200은 기존 팝업 상세에 nullable image를 포함한다. image는 `{id:UUID,url:HTTPS,expiresAt:offset datetime}`이며 존재 시 모든 필드가 필수다. 과거 응답에서 image가 생략되면 텍스트 팝업으로 처리한다. 이미지 변경 응답의 팝업 ID·증가한 version·첨부/해제 상태를 검사한다.

400 잘못된 파일/요청, 401 인증 실패, 403 관리자 아님, 404 팝업 없음, 409 오래된 version/이미 만료된 팝업, 503 S3/DB 이용 불가. 충돌·실패 시 입력을 유지하며 자동으로 업로드를 재실행하지 않는다. 서버는 최대 각 4096px/총 800만 픽셀, 실제 PNG/JPEG 형식도 확인한다.

홈의 기존 프리미엄 체험 팝업을 유지한다. 체험 안내 대상이면 먼저 그 팝업을 보여주고, 닫거나 체험을 시작한 뒤 관리자 공지를 조회한다. 체험 대상이 아니면 관리자 공지를 조회한다. 둘을 동시에 열지 않는다. 서버가 고른 관리자 공지 한 개를 표시하며 제목·본문·기존 이동 링크·닫기·일주일 숨김을 유지한다. 이미지 없는 기존 공지도 지원한다.

이미지는 서명 URL로 직접 표시하고 Next 이미지 최적화 캐시를 통과하지 않는다. 이미지 로드 실패·노출 기한 만료 시 이미지 부분만 생략하고 문구와 닫기는 유지한다. 서명은 최대 5분이며 팝업 종료를 넘기지 않는다. 서버 재조회에서 새 URL을 받는다. S3 파일의 삭제 예정일은 팝업 종료와 같고 기간을 연장하면 같이 바뀐다. 실제 S3 정리는 기본 60초 주기로 재시도하므로 약간 늦어질 수 있다. 삭제가 끝난 파일은 기간 연장으로 복원되지 않는다.

백엔드 V72/API와 S3 prefix 권한을 먼저 배포한다. AI 분석 계약은 변경하지 않는다. 운영 파일·IAM을 직접 수정하지 않았으며 브라우저 검증은 로컬 서버와 API/이미지 대역을 사용한다.

검증: 서비스·계약·숨김·체험 테스트 53개, 관리자 Chrome 34개, 홈 Chrome 14개(이미지·텍스트 전용·주간 숨김·만료/깨진 이미지와 기존 체험 포함), TypeScript·변경 파일 ESLint·webpack 프로덕션 빌드 통과. 실제 S3 업로드·삭제와 운영 IAM 적용은 배포 환경 확인 범위다.
