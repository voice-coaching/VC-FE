# 관리자 화면 정리 (2026-11-10)

- 문의 답변은 ‘문의 완료’ 한 번으로 기존 `PATCH /api/admin/inquiries/{id}/answer`를 호출한다. 기존 version·답변·사유를 전송하고 ANSWERED가 된다. 별도 처리 시작/종료 버튼은 없다. 서버의 기존 CLOSED 문의는 읽기 전용으로 유지한다. 새 상태값이나 후속 status 요청을 만들지 않는다.
- 학습 콘텐츠는 실제 클래스를 한 행으로 표시하고 설정 안에서 연결된 문장 전체를 수정·추가·제외한다. 아래 ‘독립 콘텐츠’ 목록은 `excludeClassPractice=true`를 사용한다. 백엔드는 CLASS_PRACTICE 유형뿐 아니라 실제 예문/클래스 연결이 있는 문장도 페이징 전에 제외한다. 제목으로 그룹을 추측하지 않으며 독립 받침·자음·모음 문장을 자동으로 클래스화하지 않는다.
- 승급시험은 선택한 등급에 연결된 문장과 합격 점수만 편집한다. 다른 등급 문장 검색/선택 목록과 별도 문장 등록 링크는 없다. 기존 policy/content version, 원문 수정 시 새 콘텐츠와 TTS 생성, 이미 시작한 시험 보존 계약은 유지한다. 연결 문장이 없으면 저장을 막고 안내한다.
- 회원 상세의 ‘관리자 권한’에서 관리자 지정·해제를 실행한다. 확인 창에 사유를 입력하고 서버가 권한/현재 역할을 검증한다. 본인 변경과 비활성 회원 변경은 비활성화한다. 성공 후 회원 목록/상세/이력을 갱신하고 실패·충돌은 자동 재전송하지 않는다.

## 권한 API 계약

`PATCH /api/admin/users/{userId}/role`, Bearer 및 활성 ADMIN 필수, no-store. `{expectedRole,role,reason}`를 전송한다. 두 역할은 USER/ADMIN, reason은 공백 제외 1~500자이며 모두 필수·non-null이다. 성공 공통 envelope의 data는 `{userId:number,role:USER|ADMIN}`, 필수·non-null이다. ID와 역할이 요청과 일치하는지 검증한다.

400 입력 오류, 401 인증 실패, 403 관리자 권한 없음/해제, 404 대상 없음, 409 ADMIN_EDIT_CONFLICT(기존 권한 불일치·본인·비활성 대상), 503 저장소 오류. 새로 지정된 사용자는 재로그인이 필요하며 해제된 관리자는 기존 토큰으로도 관리자 API에 접근할 수 없다. 운영자 UI로 이용등급을 관리자 권한처럼 사용하지 않는다.

백엔드 API/필터를 먼저 배포하고 프론트를 배포한다. AI 계약·스키마·마이그레이션은 변경하지 않는다.

## 검증

서비스 테스트 39개, 관리자 브라우저 32개, 승급시험 브라우저 10개, 클래스 브라우저 5개와 TypeScript·변경 파일 ESLint·프로덕션 빌드를 검증했다. 브라우저는 로컬 Next 프로덕션 빌드와 API 대역을 사용하며 운영 데이터는 수정하지 않는다. 실제 백엔드의 인증·DB·감사·동시 변경은 별도 통합 테스트 34개로 검증한다.
