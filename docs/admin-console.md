# SpeakAI 관리자 UI

## 기준과 구현 범위

프론트 origin/main **0a44c3a**에서 분리한 **feat/admin-console** 브랜치다. `/admin`을 별도 운영 콘솔로 추가했다. 기존 서비스의 파란색·둥근 카드·한글 글꼴을 사용하고 데스크톱은 좌측 메뉴, 모바일은 가로 메뉴와 단일 열로 배치한다. 기존 사용자 화면의 레이아웃·분석 경로·결제 흐름은 변경하지 않는다.

이 화면은 백엔드 관리자 1차·아나운서 음성·알림 확장 API를 사용한다. 백엔드 V62/V63/V64 및 해당 관리자 API가 배포되어 있어야 실제 데이터가 보인다. **프론트 배포만으로 API나 실제 관리자 계정이 생성되지 않는다.**

팝업 메뉴는 관리용 등록/편집 화면이다. 기존 사용자 화면에 `/api/users/me/popup`을 호출하여 실제 모달을 표시하는 변경은 이번 UI 범위에 포함하지 않았다. 알림함은 기존 `GET /api/notifications`와 string type 계약으로 ADMIN_GENERAL/ADMIN_PLAN 항목을 받는다. 브라우저 푸시·이메일·결제 자동 알림·회원 강제 등급/권한 변경 기능은 추가하지 않았다.

## 접근과 세션

- 별도 관리자 비밀번호를 만들지 않고 기존 로그인·토큰 갱신·`/api/backend` 프록시를 재사용한다.
- 먼저 `GET /api/admin/me`를 확인하고, role이 실제 ADMIN일 때만 하위 화면을 표시한다. membershipType=admin은 권한 판정에 쓰지 않는다.
- 401/403이면 관리 화면을 숨긴다. 인증 실패 후 무한 refresh를 반복하지 않는다. 로그인 버튼은 검증된 내부 next 경로로 돌아온다.
- 쿼리 키에 로그인 세션 버전을 포함하고 계정 전환 시 화면을 다시 마운트한다. 관리자 응답은 no-store이고 완료 캐시는 유지하지 않는다.
- UI 차단은 편의 기능이다. 실제 접근 통제·상태 전이·수신 대상·동시성 검증은 각 백엔드 API가 수행한다.

## 변경·오류·업로드

공개·숨김·삭제·알림 발송·대표 음성 변경·문의 상태 전이는 사유를 입력하는 확인 대화상자를 사용한다. 다른 저장 폼도 사유를 필수로 받는다. 버튼은 처리 중 중복 실행을 막고 변경 요청을 자동 재시도하지 않는다.

409에서는 입력을 유지하고 최신 상세를 다시 검토하도록 안내한다. 응답 유실·시간 초과는 성공/실패를 단정하지 않으며, 새 POST 전에 목록·상세에서 반영 여부를 확인한다. 편집 폼은 창 포커스만으로 서버 값으로 교체하지 않는다.

기준 음성은 파일 전체 SHA-256을 계산하고 서버 발급 URL·필수 헤더로 직접 PUT한다. 그 요청에는 백엔드 JWT·쿠키를 보내지 않는다. HTTP·사용자정보 포함 URL이나 인증 헤더가 섞인 업로드 계약은 거절한다. 음성은 등록 완료 전 연결됐다고 표시하지 않는다.

같은 업로드 ID와 원본 File을 현재 화면 메모리에 보존하여 등록 확인·동일 파일 재전송을 제공한다. PUT 412는 덮어쓰지 않고 같은 ID로 서버 검증을 받는다. 새 업로드를 준비하기 전 등록 목록을 확인한다. 페이지 종료나 새로고침 시 이 복구 상태는 사라지고 서명 URL도 만료된다. 미리듣기는 필요할 때 새 URL을 받고 만료 시 제거한다. 프론트 확장자·크기 검사는 보조이며 실제 오디오 디코딩·원문/버전 검증은 백엔드 책임이다.


## 최신 main 및 기존 디자인 적용

프론트 main `799af4c`에서 `feat/admin-api-integration` 브랜치를 만들었다. 기존 서비스의 글로벌 글꼴, 파란색·문자색·구분선 디자인 변수, 흰색 카드와 둥근 버튼을 사용한다. 일반 학습 화면의 배치는 유지하고, 설정에 서버의 `/api/admin/me` 검사에 성공한 계정만 보이는 관리자 진입 항목을 추가했다. 직접 `/admin`에 접근해도 별도로 권한을 검사한다. 테스트 이용등급이나 이메일로 접근 여부를 추정하지 않는다.

백엔드 PR #172의 관리자 API와 V62~V64 적용이 선행되어야 한다. 운영에 관리 API가 없거나 접근이 거부되면 화면에 가짜 데이터를 표시하지 않는다. 현재 main의 일반 기준 음성 조회는 초안도 반환할 수 있으므로, 초안 등록이 일반 사용자에게 비공개임을 보장한다고 안내하지 않는다.

최신 main 대조 후 재검증: 관리자 서비스 테스트 10개, 브라우저 15개, 기존 API 계약 90개가 통과했다. 설정 진입 항목의 서버 권한 확인과 테스트 이용등급만 있는 계정의 진입 숨김도 브라우저에서 검증했다. TypeScript와 변경 파일 ESLint가 통과했다. 이 검증의 브라우저 API/S3 응답은 테스트용 대체 응답이며 실제 운영 계정으로 글 등록·음성 업로드·알림 발송을 수행하지 않았다.

이번 화면은 관리자용 팝업 등록·편집·기간 관리까지 제공한다. 일반 회원 화면에서 `/api/users/me/popup`을 읽어 모달을 표시하는 기능은 이번 관리자 UI 변경에 포함하지 않는다.

최신 main 위 프로덕션 빌드도 성공했다. 빌드가 생성한 next-env.d.ts 변경은 원래 내용으로 복원했다.

## 콘텐츠 편집·삭제 추가 연동 (이슈 #92)

최신 main `24f19da` 기반. BE PR #174와 V65 적용 후 사용한다. 기존 관리자 디자인·컴포넌트로 공개/숨김 콘텐츠도 직접 편집하고 삭제 확인을 제공한다. 일반 사용자 화면은 이번 변경에서 수정하지 않는다.

공용 콘텐츠 4종의 편집에서 기존 ID/type/version을 사용한다. 삭제는 확인 대화상자에서 사유를 입력한 뒤 `DELETE /api/admin/contents/{id}`에 `{version,reason}`을 전송한다. 성공 응답의 id/version/deletedAt을 검사한 후 해당 상세·음성 캐시를 제거하고 목록으로 이동한다. 409/실패에는 화면과 입력을 유지하고 자동 재시도하지 않는다. 최신 상태 조회는 사용자가 직접 선택한다.

아나운서 원문을 변경하면 이전 음성이 제외됨을 안내하고, 새 version이 조회되면 이전 업로드 상태를 다시 사용하지 않는다. 제목 변경만으로 기준 음성이 제거되는 것으로 안내하지 않는다. 개별 음성 삭제나 사용자 팝업 표시는 이번 범위에 추가하지 않는다.

콘텐츠 수정·삭제 추가 검증: 서비스 테스트 13개, 브라우저 시나리오 18개, 기존 API 계약 90개 통과. 삭제 확인 전 요청 미전송, 충돌 시 미저장 입력 유지, 확인창 재개 시 이전 오류 초기화, 성공 후 목록 반영을 확인했다. 타입·변경 파일 린트·프로덕션 빌드도 검증한다. 브라우저는 API/S3 대체 응답을 사용하며 운영 콘텐츠를 변경하거나 삭제하지 않는다.

커밋 전 main을 다시 받아 `24f19da`까지 fast-forward했다. 직전 검증 기준인 `50dd458`와 파일 내용은 같고 병합 이력만 추가되었음을 확인했다.


## 회원 상세·DB 기록 삭제 및 관리자 용어 정리 (#95)

최신 main `9b5480a` 기반. BE PR #177과 V66 적용이 필요하다. 일반 사용자 UI·전역 스타일은 변경하지 않는다.

회원 상세에 이메일·동의·로그인/수정/탈퇴 시각·간편 로그인 연결 및 20개 업무 기록 분류를 표시한다. 내부 필드·상태·작업 코드는 한글로 표시하며 API 값 자체는 유지한다. 비밀번호·토큰·비밀키·내부 원본 경로·암호문은 노출하지 않는다.

회원 관리 → 상세 → ‘회원 삭제하기’에서 사유만 입력한다. DELETE /api/admin/users/{id}에 expectedUpdatedAt, reason을 전송한다. 서버 시각은 문자열 정밀도를 보존한다. 본인 관리자 계정, 서버 권한 확인 전, 최신 회원 정보가 없는 구버전 응답에서는 삭제 버튼을 활성화하지 않는다. 기존 탈퇴 회원도 DB 삭제 대상이 될 수 있다.

확인창은 회원·학습·평가·결제·문의·개인 문장 등 DB 기록 삭제와 복구 불가를 안내한다. AI 서버·별도 보관소 원본 파일은 제외하고 최소 삭제 확인·관리 작업 기록은 남긴다. 다른 회원과 공용 콘텐츠는 삭제하지 않는다.

성공 응답의 userId/deletedAt/alreadyDeleted를 확인한 뒤 상세 캐시를 제거하고 회원 목록으로 이동한다. 충돌·실패는 입력을 보존하며 자동 재요청하지 않는다. 기존 기록 보존형 POST /withdrawal은 이 PR의 최종 계약에 포함하지 않는다.

검증: 관리자 서비스 16개, 로컬 대체 API의 브라우저 시나리오 20개, 기존 API 계약 90개, TypeScript·변경 파일 ESLint·프로덕션 빌드. 운영 회원은 삭제하지 않았다.


## 회원 표시·사유 입력·조회 성능 개선 (#97)

FE main 50e2802에서 새 브랜치로 작업했다. BE #180의 탈퇴/삭제 회원 제외 및 새 삭제 DTO가 먼저 반영되어야 한다. 목록의 탈퇴 필터를 제거하고 기존 응답·캐시에도 WITHDRAWN이 있으면 화면에 표시하지 않는다. 삭제는 사유만 받으며 수정 시각은 최신 상세에서 자동 전달한다.

관리자 전반의 목록·분류·기록 조회에 API별 짧은 메모리 정책을 적용한다. 권한/수정용 상세는 새로 읽고 화면 이동마다 관리 권한을 재확인한다. 기록과 overview는 병렬로 조회하고 삭제 패널은 현재 승인한 관리자 컨텍스트를 사용한다. 변경 명령은 해당 업무와 작업 이력만 무효화하며 조회 검색·미리듣기는 캐시를 지우지 않는다. 계정 변경·권한 거부는 관리자 캐시만 제거한다.

일반 사용자 UI·디자인 및 HTTP/proxy no-store 정책은 유지한다. 루트 Providers에는 관리자 캐시 정리 구독만 추가하며 다른 기능의 캐시를 제거하지 않는다. 상세 시간·자원 분류·검증은 [API별 캐시 정책](admin-read-performance.md)을 따른다.

추가 검증: 서비스/캐시 19개, 브라우저 23개, API 계약 90개 및 타입·린트·프로덕션 빌드 통과.
