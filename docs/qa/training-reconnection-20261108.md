# 연결 복구 QA

기준: FE main `bdf3f61`, 백엔드 PR #218의 복구 계약.

## 자동 검증

검증 결과: 관련 자동 테스트 75개 통과, Playwright 복구 4개/기존 저장·승급 6개 시나리오 통과, TypeScript 및 webpack 프로덕션 빌드 통과. ESLint 오류는 없으며 기존 문장 캡처의 hook 경고 3개는 남아 있다.

- 각 단계의 서버 커밋 후 응답 유실: 세션 생성, URL 발급, PUT, 녹음 등록, 분석 요청, 명시적 retry. 같은 키/본문/파일로 복구하며 서버 생성 횟수는 1회.
- READY_TO_REGISTER는 PUT 생략, REGISTERED는 등록 생략, EXPIRED는 새 업로드 키만 사용, RECORDING_UNAVAILABLE은 새 분석 차단.
- 목록 잘림은 객체 누락으로 해석하지 않음. 503/네트워크 오류는 PUT/등록/새 분석의 근거가 아님.
- 다른 녹음/분석 시도 및 로그인 변경은 복구 중단. 재접수 영수증보다 최신 GET 우선.
- 영상은 원본 바이트/clientRequestId/세션 키/jobId/executionId/sequence 유지. 알려진 작업의 404/다른 실행은 새 작업 생성 차단.
- 실제 브라우저 IndexedDB: PUT 응답 유실 후 새로고침, 분석 접수 응답 유실 후 새로고침, 복구 조회 503 후 offline→online. 서버/저장소/AI는 대역 사용.
- 기존 canonical 저장 확정, 완료 및 승급시험 조회/채점 관련 회귀 테스트.

별도로 실행한 `scripts/sentence-sequence.test.ts`에서는 `duplicate callbacks and stale callbacks cannot skip or overwrite sentences` 1개가 실패한다. `index=2` 콜백의 예외를 기대하지만 현재 main의 구현은 빈 인덱스를 보존하는 배열을 허용한다. 해당 테스트와 구현 파일은 이번 변경에 포함하지 않았다. 위 75개 통과 결과에 이 실패 항목을 포함하지 않는다.
