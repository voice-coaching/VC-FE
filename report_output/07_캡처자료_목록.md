# SpeakAI 프론트엔드 구현 증빙 캡처 목록

현재 상태: **전체 미촬영**. 이번 작업은 운영 API·DB에 요청하지 않고 코드를 조사하였으므로 실제 실행 화면을 촬영했다고 표시하지 않았다. 아래는 프론트엔드 구현 증빙을 확보하기 위한 목록이며 디자인 제작·PPT 편집·디자인 담당자 인계 업무는 포함하지 않는다. 그림 번호 FE-01~FE-14는 통합본에서 재배정할 수 있다.

## 핵심 자료

촬영 순서는 로그인 → 홈 → 콘텐츠·클래스 → 녹음 → 분석 대기 → 결과 → 이력·마이 순으로 잡는다. 하나의 시험 계정·콘텐츠로 연결된 흐름을 확보하면 서로 다른 실행 결과를 이어 붙이는 혼동을 줄일 수 있다. 아래 표의 항목은 실제 해당 상태가 발생했을 때만 캡처한다.

| 번호·제목 | 대상 화면·경로 | 목적·강조할 구현 영역 | 권장 삽입 위치 | 상태·캡션 |
|---|---|---|---|---|
| FE-01 인증 입력·오류 처리 | `/login/email` 또는 `/signup` | 레이블, 필수 입력 검증, 제출 중 상태와 오류 안내 중 대표 1개 | 02 FE-B 인증 | 캡처 필요. ‘그림 FE-01. 사용자 입력 검증과 인증 요청 상태 표시’ |
| FE-02 홈의 학습 정보 | `/home` | 통계·진행 클래스·추천 영역. 부분 로딩 설명에는 시간순 2장 또는 별도 실행 기록 필요 | 02 FE-B 홈, FE-D 부분 로딩 | 캡처 필요. ‘그림 FE-02. 학습 현황과 콘텐츠 진입 기능’ |
| FE-03 문장 목록·필터 | `/sentences` | 서버 분류 선택지, 난이도, 목록·추가 조회 상태 | 02 FE-B 콘텐츠 | 캡처 필요. ‘그림 FE-03. 분류와 난이도를 이용한 문장 학습 목록’ |
| FE-04 클래스 상세·예문 | `/class/pronunciation` 또는 `/class/intonation` | 실제 펼쳐진 상세·단계·예문과 시작 버튼 | 02 FE-B 클래스 | 캡처 필요. ‘그림 FE-04. 클래스 정보·예문 조회와 학습 시작’ |
| FE-05 문장 녹음 | `/practice/{contentId}`의 일반 새 연습 | 현재 문장, 녹음·일시정지·다음 문장 동작과 실제 입력 상태 | 02 FE-B 녹음 | 캡처 필요. ‘그림 FE-05. 문장별 음성 녹음 진행 화면’ |
| FE-06 제출·분석 대기 | 같은 연습 화면 | 전송·분석·저장 등 실제 표시 상태. 파일 전송과 AI 처리를 한 화면의 확정 성공으로 표현하지 않음 | 02 FE-B 분석, 04 시퀀스 | 캡처 필요. ‘그림 FE-06. 분석 접수 후 결과 상태 확인’ |
| FE-07 분석 결과·교정 | 같은 연습의 결과 화면 | 제공된 종합 점수·문장 선택·코칭·발음 후보·재생 제어 | 02 FE-B 결과 | 캡처 필요. ‘그림 FE-07. 서버 분석 결과와 문장별 피드백 표시’ |
| FE-08 이력 재조회 | `/mypage/history/{sessionId}` | 동일 시험 세션의 녹음·분석 재조회와 보관 선택 상태 | 02 FE-B 이력 | 캡처 필요. ‘그림 FE-08. 학습 이력에서 다시 확인한 녹음과 분석 결과’ |
| FE-09 마이 통계·성장 | `/mypage` | 실제 통계 기간, 점수 추이, 칭호·강약점 | 02 FE-B 마이 | 캡처 필요. ‘그림 FE-09. 학습 통계와 발음 점수 추이’ |
| FE-10 내 문장 보관함 | `/my-script` | 주제·원고 목록 및 저장 후 연습 진입 | 05 FE-C 보조 화면 | 선택 캡처 필요. ‘그림 FE-10. 사용자 원고 보관과 연습 연결’ |
| FE-11 승급 시험 | `/practice/{id}?titleExamId=...` | 시험 정보·결과. 합격/불합격은 실제 서버 판정 그대로 사용 | 05 FE-C 또는 02 FE-B 시험 | 선택 캡처 필요. ‘그림 FE-11. 승급 시험의 응시 및 채점 결과 확인’ |
| FE-12 카메라 연습 | `/lip-practice` | 권한·클립 확인·분석 결과 중 대표 1개. 현재 음성 제출 범위 명시 | 02 FE-B 카메라 | 선택 캡처 필요. ‘그림 FE-12. 로컬 촬영 클립 확인과 음성 분석 연결’ |
| FE-13 배포 프로젝트 설정 | 해당 Vercel 프로젝트 설정 | Framework Preset, Root Directory, Build/Install 설정. 값이 있는 환경변수 화면은 사용하지 않음 | 03 확인된 구성 표 뒤 | 캡처 필요. ‘그림 FE-13. 프론트엔드 배포 프로젝트의 빌드 설정’ |
| FE-14 배포 상세·접속 | 해당 Vercel 배포 상세 및 배포 URL | 상태·시각·브랜치·커밋 SHA, 실제 접속 화면. HEAD와 배포 SHA를 대조 | 03 배포 결과 | 캡처 필요. ‘그림 FE-14. 확인된 배포 revision과 서비스 접속 결과’ |

본문은 핵심 FE-02~FE-09 중 설명과 겹치지 않는 자료를 우선 배치한다. 뉴스·아나운서·문장이 같은 동작을 보여 주면 세 목록을 모두 싣기보다 대표 자료 1개를 선택한다. 관리자·결제·설정 화면은 해당 구현을 별도로 설명할 때만 부록에 추가한다.

## 촬영 조건과 기록

| 확인 항목 | 기록할 내용 |
|---|---|
| 실행 출처 | 로컬/시험/실제 배포 구분, 화면이 실행한 커밋 SHA |
| 기기 환경 | 브라우저·OS·뷰포트 크기·확대율. 폭을 임의로 늘려 반응형 구현처럼 보이게 하지 않음 |
| 데이터 조건 | 시험용 계정·공개 가능한 연습 문장 사용, 해당 단계의 서버 응답 성공 여부 |
| 녹음 | HTTPS 또는 허용되는 로컬 환경, 마이크 권한·음성 길이·실제 녹음 여부 |
| 결과 | 실제 결과와 미제공 상태를 그대로 보존. 예시 점수를 넣거나 미리보기 데이터를 운영 성과로 사용하지 않음 |
| 배포 | 배포 상태와 코드 SHA를 함께 기록. 과거 성공 화면을 이번 HEAD의 성공으로 표시하지 않음 |
| 보관 | 실제 촬영 뒤 `FE-05_recording_<날짜>.png` 등으로 저장하고 이 문서의 상태를 변경 |

이름·이메일·프로필·얼굴·개인 원고, 인증 헤더·쿠키·토큰·서명 URL 쿼리는 노출하지 않는다. 편집으로 가린 부분이 있으면 설명에 비식별 처리를 명시한다. 카메라 화면은 촬영자의 동의를 받은 시험 자료를 사용한다. 이는 자료 선정 기준이며 이번 작업에서 촬영이나 업로드를 수행했다는 뜻은 아니다.

## 캡처만으로 입증할 수 없는 사항

단일 홈 이미지로 부분 로딩 속도나 API 감소율을 증명할 수 없다. 캐시·동시 갱신·재시도·음성 구간 분할은 06의 코드와 테스트 근거를 함께 사용한다. 결과 화면은 표시 구현을 보여 줄 뿐 AI 정확도·영상 모델 실행·DB 영속 저장을 독립적으로 증명하지 않는다. Mermaid 소스는 03·04에 작성하였으며 최종 편집 도구에서 렌더링과 줄바꿈을 확인해야 한다.
